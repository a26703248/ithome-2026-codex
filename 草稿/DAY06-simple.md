## 核心概念：提示詞的六個組成

**撰寫範圍（100 字內）：** 介紹任務、背景、輸入、限制、輸出格式與驗證標準六項元素，並說明不必每次都寫成冗長模板。

### 作者撰寫區塊

#### AI 建議

> 一個可重複的提示詞可以包含：目標、背景、輸入、限制、輸出格式與驗收證據。例如指定「把兩種來源的資料正規化成工作區空間統一格式」，補上目前已知的欄位清單與衝突規則，限制不新增第三方依賴，要求輸出待確認問題及每個欄位轉換規則的對照表。

## 實作示範：把壞提示詞逐步改好

**撰寫範圍（100 字內）：** 使用同一項 Java 任務比較簡略版、補背景版與可驗證版提示詞，觀察回應的相關性、假設數與可執行程度。

### 作者撰寫區塊

#### AI 建議

> 壞版本只寫「幫我把兩種資料格式對齊」；第二版補上兩種來源實際欄位、哪些必填、遇到衝突時的優先順序；第三版再限定只寫一個 Normalizer 類別、不得更動既有 API 介面，並要求回報測試命令與程式差異（diff）摘要。比較三版時，重點是輸出是否更可驗證，而不是文字是否更長。

> 建議案例：請 ChatGPT 為「跨來源欄位正規化」寫一個 Java Normalizer 類別，並補邊界條件測試。保留三版提示詞與回應摘要，並以相同評分項目比較。

## 效益與注意事項

**撰寫範圍（100 字內）：** 說明清楚提示詞能降低往返與錯誤假設，但過度模板化也可能增加負擔，應依任務風險調整詳細程度。

### 作者撰寫區塊

#### AI 建議

> 結構化提示詞能減少來回猜測，但也有維護成本。若欄位清單或衝突規則之後又改了，寫得越詳細反而越可能誤導；因此這份正規化提示詞應標示適用的欄位版本、最後驗證日期與負責人。

> 請寫下你會在什麼情況使用完整模板，什麼情況只寫短指令，以及判斷依據。
