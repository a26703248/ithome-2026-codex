## 開場情境：好提示詞只存在聊天紀錄裡

**撰寫範圍（100 字內）：** 從同一任務被不同成員重複摸索的情境開場，說明缺少共用位置、適用條件與維護責任時，經驗難以累積。

### 作者撰寫區塊

#### AI 建議

> 示例情境：AI 輔助生成系統核心的「依既有內容文件生成新文件草稿」這段提示詞，一開始只寫在某個工程師的個人聊天紀錄裡，其他人不知道當時餵了哪些結構化內容、要求引用比例怎麼算。幾週後換人調整草稿生成邏輯，也可能因為沒對齊原始限制，得到抄襲風險更高或品質不一致的草稿。

> 請描述一個團隊反覆處理的工作，例如需求整理、Code Review 或補測試。現在每個人如何操作？差異造成什麼成本？

## 核心概念：Prompt 是有輸入與驗收的工作資產

**撰寫範圍（100 字內）：** 說明可複用提示詞應包含用途、適用範圍、必要輸入、限制、輸出、驗證方法、版本與維護人。

### 作者撰寫區塊

#### AI 建議

> 團隊提示詞（Prompt）應像工作資產一樣具備名稱、目的、必要輸入、限制、輸出格式、驗收方法、範例、版本與負責人。它不保證答案正確，而是一份能被測試、審查與淘汰的工作說明——這一點對「AI 草稿生成」這種會直接影響客戶文件品質的提示詞格外重要。

| Prompt 資產欄位 | 本案例內容 |
|---|---|
| 名稱與用途 | AI 草稿生成提示詞：依既有處理完成的內容資料，生成新文件草稿 |
| 適用／不適用情境 | 待填 |
| 必要輸入 | ETL／OCR 處理完成的結構化內容、新文件的基本需求 |
| 安全限制 | 待填（需涵蓋引用既有內容的比例與方式，避免逐字抄襲） |
| 輸出格式 | 標示為「草稿」，附引用來源與待確認事項，不得暗示已具最終效力 |
| 驗證方式 | 待填 |
| 版本與負責人 | 待填 |

## 實作示範：建立一個 AI 草稿生成 Prompt

**撰寫範圍（100 字內）：** 把「AI 草稿生成」提示詞整理成團隊模板，加入範例輸入、期待輸出、引用比例的檢查方式與禁止提交的敏感資料。

### 作者驗證案例

- [ ] 使用至少兩份不同來源文件測試模板。
- [ ] 測試案例同時包含應標示引用來源與不應誤判為抄襲的內容。
- [ ] Prompt 明確要求標示草稿性質、引用來源與待確認事項。
- [ ] 失效案例（例如引用比例抓錯）與已知限制有記錄。
- [ ] 版本變更能說明修改原因與驗證結果。

## 實作示範：把 Prompt 接進複核 SOP

**撰寫範圍（100 字內）：** 說明何時使用模板、誰負責輸入、輸出交給誰、必做驗證及否決時如何回退，使 Prompt 成為流程而非貼上即用。

### 作者撰寫區塊

#### AI 建議

> 標準作業程序（Standard Operating Procedure，SOP）可規定：系統先用共用 Prompt 產生草稿與引用清單，複核人員逐項核對引用比例與敏感內容，再標註採用、修改或否決的原因；否決原因與規則變更回填到版本紀錄，避免同一個問題在下一個客戶身上重演。

```text
觸發條件：
執行角色：
輸入資料：
AI 處理步驟：
人工驗證：
通過條件：
失敗與升級處理：
維護責任：
```
