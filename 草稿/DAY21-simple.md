# Day 21｜AI 輔助 Debug 實戰

> 系列階段：第 3 週｜進階整合工作流
>
> 文件用途：作者擴寫用文章骨架，建議完稿控制在 900～1,100 字，以錯誤訊息、log、假設與實驗建立根因證據鏈。

## 開場情境：第一個合理解釋通常只是起點

**撰寫範圍（100 字內）：** 從一段容易誤導的錯誤訊息開場，說明 ChatGPT 或 Codex 提出的根因只是待驗證假設，不能直接當結論。

### 作者撰寫區塊

> 請選一個可重現的 Java 錯誤，記錄第一個直覺、模型第一個解釋，以及最後根因是否相同。

## 核心概念：症狀、假設、實驗與結論

**撰寫範圍（100 字內）：** 將除錯拆成描述症狀、排序假設、設計最小實驗與更新結論，避免一次修改多處後無法判斷原因。

## 實作示範：整理可安全分享的 Debug 套件

**撰寫範圍（100 字內）：** 準備最小重現步驟、相關程式、環境差異與去識別化 log，讓 ChatGPT 協助提出可檢驗的假設。

### 作者驗證案例

- [ ] Log 已移除個人資料、token、內部網址與完整路徑。
- [ ] 重現步驟能在明確環境穩定執行。
- [ ] 每個假設都有能證偽的實驗。
- [ ] 一次只改變一項主要變因。
- [ ] 根因與修正由測試或重現結果支持。

## 實作示範：讓 Codex 執行最小實驗

**撰寫範圍（100 字內）：** 將已排序的假設交給 Codex 執行測試、加暫時診斷或建立最小案例，再由作者比較實驗結果。

### 作者撰寫區塊

> 請保留一項被排除的假設、一項有效實驗及最後修正，並確認移除臨時 log、debug flag 與測試資料。

## 效益與注意事項

**撰寫範圍（100 字內）：** 說明 AI 可加速假設生成與程式搜尋，也可能被表面錯誤帶偏；敏感 log、環境差異及偶發問題需額外處理。

## 圖片規劃

1. 症狀與根因差異圖。
2. 去識別化錯誤與 log。
3. 假設排序表。
4. 最小實驗與結果。
5. 根因、修正與回歸測試。
