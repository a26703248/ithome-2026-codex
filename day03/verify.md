# Day 03 驗證、考察與實作紀錄

本檔保存 Day 03 的實驗設計、五次 ChatGPT 實測、差異計數、責任邊界檢查、限制及發布前驗收，並以問題追蹤項目（Issue）及人工智慧（Artificial Intelligence，以下簡稱 AI）協作為範圍。目標是讓第三人能依相同輸入重做實驗，並能區分「格式一致」「文字一致」「語意近似」與「內容有證據」。

本檔所稱應用程式介面（Application Programming Interface，以下簡稱 API）是軟體彼此交換資料與呼叫功能的約定。

## 一、今日要驗證的核心命題

### 命題 A：相同提示的完整輸出是否逐字相同？

**驗證方法**：

1. 固定同一筆原始回報。
2. 固定完整提示詞與欄位順序。
3. 每次開啟沒有前文的新對話。
4. 依序執行五次並保存完整輸出。
5. 比較整份回答及各欄位的逐字內容。

**驗收結果**：

- [x] 五次均收到完整回答。
- [x] 五次均出現六個指定欄位。
- [x] 五份完整回答皆不完全相同。
- [x] Title 與 Actual Result 五次逐字相同。
- [x] Summary、Expected Result 與 Triage Status 均有五種文字版本。

### 命題 B：語意近似是否等於可以直接交給程式使用？

**驗證方法**：比較 Triage Status 的五種文字，判斷人類可理解的共同方向是否等於程式可用的固定狀態值。

**驗收結果**：

- [x] 五次都指向資訊不足、需要補充或確認。
- [x] 五次文字均不相同。
- [x] 結論明確區分語意一致與字串一致。
- [x] 未將自由文字直接定義成正式工作流程狀態。

### 命題 C：格式完整是否代表遵守證據邊界？

**驗證方法**：檢查每次 Expected Result 是否可追溯原始回報，並依提示中的「不知道請寫未知」規則判定。

**驗收結果**：

- [x] 原始回報未提供 Expected Result。
- [x] 五次都補寫「應正常完成／運作」等一般性預期。
- [x] 符合「未知」規則的執行為 0／5。
- [x] 文章沒有把這些生成內容當成已確認產品規格。

### 命題 D：Missing Information 是否每次產生相同清單？

**驗證方法**：保存原始順序及文字，再建立逐項出現矩陣。

**驗收結果**：

- [x] 每次產生 8～9 項。
- [x] 五次均包含發生環境、頻率、重現步驟、錯誤訊息、作業系統及版本概念。
- [x] 帳號類型、網路環境、發生時間、使用裝置及可重現性只在部分執行出現。
- [x] 結論指出必問清單需要由固定規則保證。

## 二、實驗輸入與環境考察

### 原始回報

```text
登入功能怪怪的，有時候會失敗。
```

來源：`day01/raw-issues.md` 的第一筆原始回報。

### 完整提示詞

```text
請將以下使用者回報整理成一張可處理的軟體 Issue。
只能使用原文提供的資訊；不知道的內容請寫「未知」，不可自行補充。
請依序輸出：
1. Title
2. Summary
3. Actual Result
4. Expected Result
5. Missing Information
6. Triage Status

使用者回報：
登入功能怪怪的，有時候會失敗。
```

提示詞的完整獨立版本保存在 `prompt.md`。

### 因果推論限制

本次觀察到輸出差異，但不能把差異歸因於特定模型、溫度、種子或路由，因為這些資訊在使用的網頁介面不可見。可驗證陳述限於：

> 2026-07-29，在上述未登入網頁介面與固定提示下，五次新對話產生五份不完全相同的完整回答。

不能由本次資料推導：

- 所有 ChatGPT 模型都會以相同方式變動。
- 任一欄位具有一般性的穩定率或錯誤率。
- 差異一定由某個抽樣參數造成。
- 登入帳號、使用 API 或日後重做會得到相同分布。

## 三、實作內容

### 實作 1：建立固定實驗包

產出：

- `prompt.md`：原始回報、完整提示與環境限制。
- `raw-responses.md`：五次未修正輸出。
- `comparison.md`：逐欄比較、計數及責任層級。
- `conclusion.md`：工程結論、限制與下一步。
- `note.md`：可直接發布的 Day 03 文章。

保存原始輸出與分析檔分開，避免後續統一用詞時破壞原始證據。

### 實作 2：執行五次沒有前文的新對話

每一次執行以下步驟：

1. 開啟 `https://chatgpt.com/` 的新對話頁面。
2. 確認輸入區沒有先前訊息。
3. 貼上 `prompt.md` 的完整提示。
4. 送出後等待回答完成。
5. 保存六個欄位的完整文字。
6. 不追問、不要求重寫、不把輸出帶入下一次。

五次實際輸出均保存在 `raw-responses.md`。

### 實作 3：逐欄比較

比較規則如下：

| 檢查層次 | 比較方法 | 本次證據 |
| --- | --- | --- |
| 結構 | 檢查六個欄位是否存在 | 5／5 完整 |
| 逐字 | 比較欄位完整字串 | Title、Actual Result 為 5／5 相同 |
| 語意 | 人工判讀核心意思 | Triage Status 方向相同 |
| 集合 | 比較 Missing Information 項目 | 每次 8～9 項，集合不同 |
| 證據 | 對照原始回報與未知規則 | Expected Result 為 0／5 合規 |

這是描述性比較，不是 Day 04 的品質評分表。

### 實作 4：建立 Missing Information 出現矩陣

| 項目 | Run 1 | Run 2 | Run 3 | Run 4 | Run 5 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 發生環境 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 發生頻率 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 重現步驟 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 錯誤訊息 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 使用裝置 | ✓ | ✓ | ✓ | ✓ |  |
| 作業系統 | ✓ | ✓ | ✓ | ✓ | ✓ |
| App／網站／瀏覽器版本 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 帳號類型 | ✓ | ✓ |  |  |  |
| 發生時間 | ✓ | ✓ | ✓ |  | ✓ |
| 網路環境 |  |  | ✓ | ✓ |  |
| 是否可穩定重現 |  |  |  |  | ✓ |

矩陣只做文字正規化，例如把 `App／瀏覽器版本`、`App／網站版本` 與 `瀏覽器／App 版本` 放在同一版本概念列；不把「發生環境」與裝置、作業系統、網路環境強行視為同一項。

### 實作 5：套用 Day 02 責任層級

| 產出 | 層級 | 實作控制 |
| --- | --- | --- |
| 原始回報 | L0 | 與 AI 輸出分開保存 |
| Title、Summary、Actual Result | L1 | 標示為 AI 草稿並保留來源 |
| Missing Information | L2 | 作為追問候選，由分流者排序 |
| Triage Status | L2 候選；正式狀態轉換涉及 L3 | 先映射受控候選，不直接觸發狀態 |
| Expected Result | L3 相關 | 沒有規格就保持未知，由規格擁有者確認 |

### 實作 6：形成後續系統需求

Day 03 不提前撰寫 Day 09 的結構化格式或 Day 26 的 API，但先記錄七項需求：

1. 原始回報不可被 AI 草稿覆寫。
2. 每個欄位要獨立驗證。
3. 未知值要有明確且一致的表示。
4. 必問資料由固定規則或結構描述（Schema，也就是欄位與格式規則）保證。
5. 流程狀態採受控列舉值。
6. 記錄可見模型標籤；不可見資訊標示未知。
7. 重要案例要重複執行，不能只保存成功樣本。

## 七、限制

- 本次只有一個案例、一份提示與五次輸出。
- 未登入介面背後的精確模型、溫度、種子與路由未知。
- 五次在同一瀏覽器工作階段中執行，並非五個完全隔離的使用者環境。
- 只保存實驗完成時間，沒有逐次時間戳。
- 沒有保存公開聊天連結，避免把臨時或私有工作階段當成長期證據。
- 沒有以截圖代替文字證據；原始內容以 `raw-responses.md` 保存。
- 本日只做描述性比較，尚未建立品質門檻或統計推論。
