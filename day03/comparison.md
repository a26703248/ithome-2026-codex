# Day 03 多次輸出差異比較

本檔只描述五次輸出的相同與不同，不在 Day 03 提前建立 Day 04 的品質評分標準。

## 一、逐欄比較

| 欄位 | 結構出現率 | 逐字結果 | 語意觀察 | 證據邊界 |
| --- | ---: | --- | --- | --- |
| Title | 5／5 | 五次完全相同 | 都描述登入有時失敗 | 可追溯原文 |
| Summary | 5／5 | 五種文字 | 核心症狀相同；Run 4、5 增加「並非每次」「不固定」的轉述 | 仍可由「有時候」支持 |
| Actual Result | 5／5 | 五次完全相同 | 都保留「登入有時失敗」 | 可追溯原文 |
| Expected Result | 5／5 | 五種文字 | 都假設登入應正常完成或運作 | 原文未提供預期結果；依固定提示應為「未知」 |
| Missing Information | 5／5 | 五組清單均不完全相同 | 每次 8～9 項；核心缺口重疊，帳號類型、網路環境、時間及可重現性等項目有增減 | 屬追問建議，不是已知事實 |
| Triage Status | 5／5 | 五種文字 | 都指向需要補充或確認資訊 | 屬流程建議，不應直接觸發狀態轉換 |

## 二、計數結果

| 指標 | 結果 | 判讀 |
| --- | ---: | --- |
| 完整輸出數 | 5 | 五次均收到回答 |
| 具備六個指定欄位的輸出 | 5／5 | 結構層在本次樣本中一致 |
| 與其他執行完全重複的完整回答 | 0／5 | 五份完整輸出皆為不同版本 |
| Title 逐字相同 | 5／5 | 本次樣本穩定 |
| Actual Result 逐字相同 | 5／5 | 本次樣本穩定 |
| Summary 的不同文字版本 | 5 | 核心語意近似，表達不同 |
| Expected Result 的不同文字版本 | 5 | 表達不同，且都跨越證據邊界 |
| Expected Result 符合「未知」規則 | 0／5 | 本次最明確的指令遵循失敗 |

## 四、責任層級對映

| 差異 | Day 02 層級 | 可接受用法 | 不可直接做的事 |
| --- | --- | --- | --- |
| Title、Summary、Actual Result 的措辭差異 | L1：AI 整理 | 作為有來源的草稿，人工對照原文 | 覆寫原始回報 |
| Missing Information 的清單差異 | L2：AI 建議 | 提供追問候選，由分流者排序 | 把每次遺漏的項目當成不重要 |
| Triage Status 的表示差異 | L2 候選；正式狀態轉換涉及 L3 | 映射到受控狀態候選 | 直接用自由文字觸發流程 |
| Expected Result 的補寫 | 涉及 L3：規格擁有者決定 | 標示未知，向規格擁有者查證 | 把常識推測寫成正式需求 |

## 五、可重現結論

本次五份回答呈現三種同時存在的現象：

1. **結構穩定**：六個指定欄位都出現。
2. **局部文字穩定**：Title 與 Actual Result 五次逐字相同。
3. **內容與證據邊界不穩定**：追問清單、狀態文字與 Expected Result 都有差異；Expected Result 還在五次中都違反「未知」規則。

因此，不能只問「答案一不一樣」。工程上至少要分別檢查結構、文字、語意、集合與證據合規。
