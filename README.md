# 30 天把 ChatGPT 與 Codex 放進軟體開發流程

這是我參加 **2026 iThome 鐵人賽「ChatGPT & Codex」主題競賽**的系列文章總覽。

我想處理的問題不是「生成式 AI 能不能寫程式」，而是更貼近日常工作的幾個問題：需求還很模糊時，怎麼請 ChatGPT 協助釐清？面對一個真實的程式碼庫，怎麼把任務交給 Codex 執行？AI 改過的程式碼要如何測試、審查與追蹤？當使用方式從個人實驗擴大到團隊流程，又該如何管理權限、成本與風險？

這 30 天會從基本心智模型出發，逐步走過需求分析、系統設計、程式開發、測試、除錯、文件維護、Git 協作與團隊治理。我會用實際或改編自實務的開發情境，記錄有效的方法，也保留失敗、誤判與需要人工把關的部分。

## 這個系列適合誰？

這個系列寫給參與軟體開發流程的各種角色，包括後端與前端工程師、QA、PM、DevOps／SRE、技術主管及 UI／UX 設計師。讀者不需要具備人工智慧或機器學習背景；只要熟悉基本的軟體開發流程，並且想知道如何把 ChatGPT 與 Codex 用在真實工作中，就能跟著系列逐步練習。

程式碼範例會以 **Java** 為主，視情境搭配 Maven 或 Gradle、JUnit 5 與 Spring Boot。即使主要使用其他程式語言，也可以把文章中的任務拆解、提示詞設計、驗證方式與安全原則套用到自己的技術棧。

## 30 天學習路線

整個系列分成五個階段：

1. **建立心智模型（Day 1–3）**：先分清楚 ChatGPT 與 Codex 的定位、能力邊界及使用場景。
2. **需求、設計與溝通（Day 4–9）**：把 ChatGPT 用在寫程式以前的分析、規格、學習與審查工作。
3. **Codex 基礎實作（Day 10–16）**：理解代理工作模式，完成讀取專案、修改程式碼、執行測試及 Git 協作的基本流程。
4. **進階整合工作流（Day 17–23）**：練習大型重構、測試維護、Legacy Code 考古、除錯及品質把關。
5. **團隊、流程與治理（Day 24–30）**：把個人技巧擴大為可重複、可量測、可治理的團隊能力。

## 我會如何呈現每一篇文章？

除前言與總結外，每篇文章原則上都會從一個開發現場的問題開始，接著說明必要觀念，再提供可以跟著操作的提示詞、指令、Java 程式碼、圖示或截圖。實作之後，我也會交代它節省了什麼、可能在哪裡失敗，以及哪些結果仍然必須由人判斷。

這個系列不把 ChatGPT 或 Codex 當成能夠獨立負責成果的黑盒子。我的基本原則是：**讓 AI 加速探索與執行，讓人負責目標、限制、驗證與最終決策。**
