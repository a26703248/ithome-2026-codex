## 四、建議實作：建立 Day 28 可回看的基準線

### 任務選擇

在你有權使用且不含敏感資料的 Java 專案中，選一個 30～90 分鐘可完成的小任務。優先選擇有明確驗收條件、能執行自動化測試的項目，例如：

- 為 Spring Boot 請求物件補上欄位驗證與錯誤測試。
- 為既有 service 的邊界條件補一個 JUnit 5 測試。
- 修正一個能用測試穩定重現的 null 處理缺陷。

### 實作步驟

1. 先寫下原始 issue、已知限制與驗收條件。
2. 記錄開始時間與目前測試狀態。
3. 將需求交給 ChatGPT，只要求它提出澄清問題與風險，不先產生修正碼。
4. 回答澄清問題，整理成一份可執行的任務說明。
5. 將任務交給 Codex，記錄它讀取的檔案、執行的指令、修改內容與測試結果。
6. 人工檢查 diff，記錄退回、修正與補充提示的次數。
7. 重新執行完整驗證，確認結果是否符合原始驗收條件。
8. 記錄結束時間，保留 Day 28 能比較的資料。
