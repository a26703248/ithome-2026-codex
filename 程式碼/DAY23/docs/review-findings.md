# Day 23 初篩與人工複核

本檔為作者依初篩回覆整理的紀錄，不是完整原始對話逐字稿；讀者可重跑 `review-prompt.md`，但模型輸出不保證逐字相同。

## Codex 初篩確認

- `ReportController-before.java.txt` 只取得登入者身分，沒有確認該身分能操作路徑中的 `customerId`。縮小測試以 `alice` 存取 `cust-002`，應回傳 403 且不得呼叫報表服務。
- `pom.xml` 固定 Apache PDFBox 2.0.23。官方通知指出此版本在載入特製 PDF 時受 CVE-2021-31811 與 CVE-2021-31812 影響；目前縮小路徑只建立新文件並輸出，沒有找到載入外部 PDF 的呼叫，因此無法證明通知在此路徑可被觸發。正式系統程式與相依清單未提供，維持待確認。

## 人工複核補充

- 初篩沒有列出 `ReportController-before.java.txt` 把完整收件信箱寫入日誌。修正版只記錄請求代號、客戶代號與格式。
- 縮小專案沒有 API 閘道、限流、佇列容量或跨節點重複請求的設定。這是證據缺口，不宣稱正式系統一定缺少保護。

## 修正與證據

- 修正版把格式改為列舉，並限制客戶代號、檔名與信箱的格式及長度。
- 控制器把授權判斷委派給 `ReportAccessPolicy`；正式政策實作不在縮小案例，測試只以替身指定允許或拒絕。
- JUnit 覆蓋缺少身分物件、授權政策拒絕、錯誤客戶代號、未知格式、已授權請求獲得受理，以及 PDF 輸出檔頭。
- PDFBox 警示另開升級與完整呼叫路徑盤點工作，不以本篇縮小案例直接結案。
