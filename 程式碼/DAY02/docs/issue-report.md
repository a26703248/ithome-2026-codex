# Issue Report — 商品查詢結果異常

> 本文件為 Day02 文章「任務一：釐清模糊需求」的產出範例，
> 由原始回報「站台的查詢結果好像怪怪的」，經與 ChatGPT 多輪追問後整理而成。
> 交給 Codex 修正前，須連同本文件、product-spec.md 與現有程式碼一併提供。

## 原始回報

站台的查詢結果好像怪怪的（PM 轉述使用者反應，重新操作一次無法重現）。

## 釐清後的問題描述

1. **關鍵字查詢遺漏結果**：使用者以小寫關鍵字（例如「iphone」）查詢商品，
   預期應同時看到「iPhone 15 Pro」與「iphone 13」，但實際只看到部分結果。
2. **跨頁排序不一致**：以價格由高到低排序並瀏覽第 2 頁時，
   部分商品的價格排序與第 1 頁銜接不上，懷疑排序是分開套用在每一頁而非整體結果。

## 重現步驟

1. 呼叫商品查詢 API，關鍵字輸入「iphone」（全小寫），分類不限。
2. 觀察回傳結果是否包含名稱含大寫字母的商品。
3. 另外呼叫查詢 API，依價格由高到低排序，`page=0` 與 `page=1`、`size=3`，
   比對兩頁串接後的順序，是否等同於「先排序、再切頁」的結果。

## 影響範圍

- 商品查詢 API（`ProductSearchService#search`）。
- 使用情境：後台人員以關鍵字或排序瀏覽商品清單、換頁查看。

## 未確認 / 暫不列入本次修正

- 關鍵字前後空白、特殊字元的比對行為。
- 大量資料下的查詢效能。
- 這兩點留待後續需求釐清，避免修正範圍擴大（見 product-spec.md 第 5 節）。

## 驗收條件（草稿，待 PM／QA 共同確認）

- [ ] 以任意大小寫輸入關鍵字，均能查到名稱包含該關鍵字（忽略大小寫）的商品。
- [ ] 同一組排序條件下，逐頁串接的結果順序與「整體排序後切頁」一致。
- [ ] 既有的分類篩選行為不受影響（回歸測試）。
