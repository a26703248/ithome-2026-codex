# Day 24 跨角色交付紀錄

本文件是依 `案例/AI輔助生成系統-需求書.md` 製作的桌上演練，不是已上線系統或真實跨部門會議紀錄。

## 已確認

- 系統只產生草稿，不提供自動核准或自動發布。
- 需求書要求保留草稿版本、操作紀錄，以及採用、修改或否決的原因。

## 本次最小驗收

- 每種決策的複核原因都不可空白。
- 修改新增版本，不覆蓋原始草稿。
- 採用、修改、否決都新增複核事件。
- `mvn clean test` 的 4 項測試必須通過。

## 待角色確認

| 待確認事項 | 建議責任角色 | 可接受的驗收證據 |
|---|---|---|
| 敏感內容遮蔽與分級 | 法遵／資安 | 核定規則、權限測試與設定 |
| 載入、儲存失敗、唯讀與衝突狀態 | 設計、PM、QA | 介面稿、可用性檢查與測試案例 |
| 正式身分與客戶資料授權 | 工程、資安 | 整合測試、設定與審查紀錄 |
| 留存、刪除與封存 | 法遵、維運 | 核定政策、排程與稽核紀錄 |
| 監控、告警與復原 | 維運 | 儀表板、告警演練與復原紀錄 |

## 部署判斷

目前只有最小 Java 契約與單元測試證據，不具備正式部署條件。正式系統仍須完成上述待確認事項，並由對應角色簽認。
